## GLOBAL TEMPORARY FULL-SUITE POLICY — **ACTIVE** (2026-08-19)

**Canonical:** `docs/governance/global-temporary-full-suite-policy.md` · **rule mirror:** `.cursor/rules/107-global-temporary-full-suite-policy.mdc` (`alwaysApply: true`). Status **ACTIVE / TEMPORARY / user-authorised / global across the current corrective-fix series**. Governance + docs + rules only — **no runtime, config, CI, schema, permission or deploy change** (this change set is deliberately `docs_only`, verified with `scripts/ci/resolve-gates.sh`, so enabling the policy cannot itself fire the gate it governs).

**The rule.** While ACTIVE, an **individual fix sprint MUST NOT run the Full Suite**. It is **deferred** — never removed — to **one authoritative consolidated run on the frozen final integrated SHA** once every planned fix is complete. Rationale: repeating an *integrated* gate after each fix re-validates a SHA the next fix immediately invalidates. Never write "the Full Suite is unnecessary"; the correct statement is "the Full Suite is deferred."

**Nothing else is relaxed.** Every fix still requires targeted tests, **dependency-aware cumulative regression** (derived from `sprint:test-plan` + `graphify`, never the whole repo and never too little), security + architecture review, `pint`, `git diff --check`, permission/module suites, **all required non-Full-Suite CI gates** (NSF-R012 Quality, CICD-CTRL Classifier, NSF-R011 Critical, CICD-CTRL Selective Module, NSF-9 Release Safety & Smoke, NSF-10 Release Evidence), merge + deploy verification, production smoke, rules sync, cleanup. *"Full Suite skipped, therefore other tests may be skipped"* is **forbidden reasoning**.

**Biggest accidental-trigger risk is LOCAL, not CI.** `php artisan sprint:test --all-required` (and `--regression`) appends a `pest-full-required` step that runs **bare `php artisan test` — the whole repository** whenever `escalate_full_suite` is true, and escalation is **fail-closed** (a changed file matching an escalation category *or no category at all* sets it; `.sprint/current.yml` matches nothing). The canonical sprint template otherwise tells every sprint to run exactly that before release — **while this policy is ACTIVE that instruction is superseded**. Use `sprint:test-plan` (read-only) + `sprint:test --focused` (never escalates) + `vendor/bin/pint --dirty --test` + `git diff --check` + `php artisan test --filter='<targeted regression>'`.

**CI mechanics (verified, not assumed; superseded in part by CI-TEMP-FULL-SUITE-SCHEDULE-GATE — see that section below, where BOTH automatic triggers are now gated in CI).** Before that gate, `full_suite_gate` fired on exactly three events: `pull_request` → **never** (so a fix sprint's own PR is structurally `FULL_SUITE_EXECUTION_COUNT=0`); **`push` to base → fires** (a squash-merge *is* such a push); `schedule` (weekly `0 2 * * 0` UTC) → fires, calendar-driven and attributable to no sprint; `workflow_dispatch` + `run_full_suite=true` → deliberate and **forbidden while ACTIVE**. **Gotcha:** `.sprint/current.yml` matches no classifier pattern and falls through to `unknown_high_risk`, so because every real sprint updates its manifest, **every real fix merge enables the post-merge Full Suite step** — only a genuinely docs-only change set resolves to `docs_only` and skips it. Always resolve the profile with `scripts/ci/resolve-gates.sh` before pushing; never guess.

**Post-merge run handling (precedent: FIX-LEGACY-RME-ROUTINE-OPS-1, run `32205563992`).** An official `gh run cancel` is permitted **only** when the pre-merge candidate was green on an **identical tree** (cancelling also cancels the other gates in that run), the cancel lands **before the Full Suite job begins executing tests**, the run ID + `startedAt == completedAt` zero-duration proof are recorded, and **no CI file is touched**. **Forbidden:** cancelling a Full Suite that has already begun executing in order to report a zero count — that is an execution; record it and report the partial result. Never cancel a *scheduled* run for count management; a scheduled run is an informational baseline and can never be cited as a fix sprint's Full Suite pass.

**Evidence — read the STEP, never the job.** Verified on real runs: on a **docs-only push to base the `NSF-R011 Full Suite Gate` job reports `success` while the suite never executed** (classifier resolves `docs_only` → `Run full Pest suite` = `skipped`, and a `Note skipped full suite (docs-only change)` step writes the evidence; nothing failed, so the job is green). Run `32211741144` on `1311dba` is the worked example. So the rule is not merely "job skipped ≠ passed" — **`success` ≠ tests passed**; a green Full Suite job proves only that nothing *errored*. Verify with `gh run view <id> --json jobs --jq '.jobs[]|select(.name=="NSF-R011 Full Suite Gate")|.steps[]|select(.name|test("full Pest suite"))|"\(.conclusion)\t\(.name)"'`; the run-level `conclusion=success` from `gh run list` is an aggregate and says nothing about execution.

**Evidence.** Every report states `FULL_SUITE_STATUS = SKIPPED_BY_GLOBAL_TEMPORARY_POLICY`, `FULL_SUITE_EXECUTION_COUNT = 0`, `GLOBAL_TEMPORARY_FULL_SUITE_POLICY_ACTIVE = YES`. **Job skipped ≠ tests passed. Job cancelled ≠ tests passed.** Never claim a pass that did not run; if an accidental Full Suite genuinely runs, record run ID/SHA/event/result, report the breach, and never rewrite history to protect a count. Historical GO tags and CI runs are **immutable** — this policy is prospective only.

**Closure + GO tags.** A finished fix closes at **`WATCH — PENDING CONSOLIDATED FULL SUITE`** — a valid closure, not a failure; distinguish *implementation closure* (reached) from *final integrated verification closure* (deferred). **No final engineering GO tag** for a fix whose governance requires a Full Suite before GO. The consolidated closure (policy §9) starts **only** on explicit user authorisation: inventory WATCH sprints → verify merged+deployed → freeze the final SHA → baseline re-verify → **one** Full Suite (expected failures **0**) → production smoke → governance audit → GO decision → tags. On failure: **NO FINAL GO**, record the exact failure set, **do not immediately rerun**, diagnose with targeted tests, fix, merge/deploy, then agree the next authoritative run with the user.

**Unchanged:** deployment (`bash scripts/deploy-vps-runner.sh start` **on the VPS**, real `exit=0` + `DEPLOY OK`, backup first, `migrate --force` only, never `migrate:fresh`/`db:wipe`), production smoke over `https://daengtisia.online`, Legacy RME fail-closed / RM-derived branch authority / read-only archive / maker ≠ publisher / creator ≠ approver / admission EMPTY + capability OFF at rest, CICD-CTRL-1 default-strong classification, branch isolation, ledger-only inventory, RBAC 3-layer, PII masking, additive-only migrations. **This policy changes test scheduling only.**

**Retirement:** ends only on explicit user revocation **or** completed consolidated closure — one finished fix does not end it. On retirement, mark the doc and rule `RETIRED after consolidated Full Suite closure`; **never delete them.**

**Deferred inventory:** `FIX-LEGACY-RME-ROUTINE-OPS-1` — WATCH, Full Suite skipped (count 0), **no GO tag**; runtime authority `acbf5e3`, docs-only `1311dba` undeployed. Per explicit user decision **do not create a `FIX-LEGACY-RME-ROUTINE-OPS-1A` closure sprint now** — it folds into the single consolidated closure. Append a row to policy §12 for each further fix shipped under this policy.
