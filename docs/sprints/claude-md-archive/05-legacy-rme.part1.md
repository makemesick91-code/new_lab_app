## LEGACY-RME-PDF-1A — Legacy RME PDF Archive Foundation: Schema, Permission & Date Rules (2026-08-06)

Branch `feature/legacy-rme-pdf-1a-schema-permission-date-rules` (base `feature/sprint-26-phase-26-8-stabilization-closure-go-watch-no-go-report`, baseline SATUSEHAT-4D merge `3cd6452`; do NOT target main). Sprint doc `docs/sprints/legacy-rme-pdf-1a-schema-permission-date-rules.md`; ADR `docs/adr/0008-legacy-rme-pdf-archive-foundation.md`; rule mirror `.cursor/rules/90-legacy-rme-pdf-archive.mdc`; manifest `.sprint/current.yml`. **Foundation for "Import Arsip RME Lama Pasien" — the PDF a Super Admin will later upload is the patient's HISTORICAL RME data, not a template and not a live-workflow RME.** Operated from **Master Data → Master Data RME → Import Arsip RME Lama**. **Scope 1A = schema, permissions, policies, repositories, date-rule domain, audit foundation, config, tests ONLY.** Deliberately NOT shipped: PDF conversion/Poppler/Imagick/OCR/canvas/PDF.js, upload runtime, annotation, thumbnails, publish runtime, patient-timeline integration, doctor viewer, legacy print/PDF — and **no route, controller or Blade view exists in 1A** (an endpoint was not added merely for coverage; services are tested directly). Feature flag `rme.legacy_pdf_archive` (`FEATURE_RME_LEGACY_PDF_ARCHIVE`, risk `high`) **defaults OFF**, resolved via `LegacyRmeFeatureGuard`→`FeatureFlagService` (never `config('feature_flags…')` — dots break traversal). New bounded context `App\Modules\LegacyRme` (Interfaces/Models/Policies/Repositories/Services/Support; no module provider — bindings + policies go in `RepositoryServiceProvider`'s `private array $repositories`/`$policies`).

**Migrations (additive only — `migrate`, never `migrate:fresh`/`db:wipe`):** `2026_08_06_100001..4` create `stg_rme_legacy_imports`, `stg_rme_legacy_import_pages`, `trx_rme_legacy_records`, `trx_rme_legacy_record_pages`. Legacy records are deliberately NOT stored in `trx_medical_records` (which requires a NOT NULL + UNIQUE `clinic_visit_id` and drives the visit→cashier workflow) — a legacy RME has **no `clinic_visit_id` and never creates a fake visit**. Constraints: `UNIQUE(uuid)`, `UNIQUE(legacy_import_id,page_number)`, `UNIQUE(rme_legacy_record_id,page_number)`, **`UNIQUE(source_import_id)`** (one staging batch → at most one record, publishing idempotent), indexes on `(patient_id,rme_date)`, `(patient_id,status)`, `source_pdf_sha256`, `normalized_content_hash`. `source_pdf_sha256` is intentionally **not globally unique** (cross-patient duplicate investigation + VOID-then-reimport need repeats). Staging soft-deletes; **published tables carry NO soft delete** — immutability is the contract. FK posture: patient/branch RESTRICT/NULL (never cascade clinical rows), staging pages cascade with their batch, published pages RESTRICT (evidence).

**Domain contract (permanent, mirrored in rule 90):** (1) legacy RME = archive of a patient's OLD RME data from a historical PDF; (2) never creates a clinic visit, invoice, payment, consent, odontogram, `LabCaseCandidate`, `LabOrder` or SATUSEHAT candidate, never changes visit status, never enters visit/revenue KPI; (3) the date is **chosen manually** from what the document shows — never upload time / `created_at` / file date / PDF metadata / OCR — stored as `selected_rme_date` (staging) / `rme_date` (published), separate from `uploaded_at`/`published_at`; (4) **`legacy date < earliest_native_rme_date` STRICTLY** (equal = rejected, since equal is exactly the overlap case) **when a native RME exists — widened by FIX-ROLL2-1 to every date the document represents (`latest < earliest native RME`)**, plus `legacy date < today` (**today is rejected** — an archive is historical) and `patient birth date <= legacy date` (**equal to the birth date is accepted**); `mst_patients.date_of_birth` is nullable so a missing value **skips** that rule and is never invented; (5) **SUPERSEDED by LEGACY-RME-PDF-FIX-ROLL2-1** — 1A refused a patient with no native RME (`PATIENT_HAS_NO_NATIVE_RME`); such a patient is now ELIGIBLE (the native RME is a bound, not a prerequisite) and a native encounter is never manufactured to unlock an import; (6) an existing legacy row (staged/published/**VOID**) is never native RME and never becomes the comparison point; (7) a published record is **immutable** — correction is **VOID with a reason + fresh import**, never an in-place edit or hard delete.

**Canonical clinical date:** `earliest_native_rme_date` derives from **`trx_clinic_visits.visit_date`** via the visit that owns the medical record. `trx_medical_records` has **no clinical date column at all**. Rejected (each a real trap): `created_at` (Sprint 59 removed the finalize lock + Sprint 64.0 lets a doctor open a sheet from a later visit → row written long after the encounter), `finalized_at` (nullable workflow timestamp), `canonical_visit_id` (a cache — its own migration says the resolver is the live source of truth), `mst_patients.registered_at` (administrative). **Single source of truth = `App\Modules\LegacyRme\Services\PatientEarliestNativeRmeDateResolver`** backed by new `ClinicVisitRepository::earliestVisitWithMedicalRecordForPatient(int $patientId)` (+ interface) — no controller/FormRequest/policy/view/test may re-derive it. Excludes cancelled visits, visits without an MR, soft-deleted visits/records, and every legacy row; orders `(visit_date, id)` for PG/SQLite stability. **Deliberately NOT branch-scoped** (diverges from `PatientRmWorkspaceResolver::resolveCanonicalVisit()` on purpose, pinned by a test): a narrower scan could only move the bound LATER and admit an overlapping document — access control is a separate concern. **Timezone:** "today" uses `legacy_rme.dates.clinical_timezone` (defaults to the app timezone — the same wall clock `ClinicVisitService` uses when stamping `visit_date` via `Carbon::today()`), and `visit_date` is treated as an opaque calendar date and never shifted; realigning the setting moves the boundary by at most one calendar day.

**Rules service:** `LegacyRmeDateRuleService` with stable codes (`PATIENT_HAS_NO_NATIVE_RME` **removed by FIX-ROLL2-1**; `LEGACY_DATE_RANGE_INVALID` added) `LEGACY_DATE_NOT_BEFORE_NATIVE_RME`, `LEGACY_DATE_IN_FUTURE` (covers today + future), `LEGACY_DATE_BEFORE_PATIENT_BIRTH`, `LEGACY_DATE_INVALID`; `evaluate()` returns an immutable `LegacyRmeDateRuleResult` (branch on the CODE, never the message), `assert()` throws `ValidationException`, `snapshotCutoff()` produces the server-side `earliest_native_rme_date_snapshot` — **the cutoff is always recomputed server-side; a client-supplied snapshot is never trusted**. The rule context is PII-free by construction (dates + `patient_id` only).

**Status domain:** no native PHP `enum` exists anywhere in `app/`, so vocabularies are final Support classes + model constants — `LegacyRmeImportStatus` (`DRAFT→UPLOADED→QUEUED→PROCESSING→READY_FOR_REVIEW→REVIEWED→PUBLISHED` + `FAILED`/`CANCELLED`, explicit `TRANSITIONS`, terminal = PUBLISHED/CANCELLED), `LegacyRmeImportPageStatus` (fail-closed: default `PENDING`, only `READY` is publishable), `LegacyRmeRecordStatus` (`PUBLISHED→VOID` only).

**RBAC (5 new permissions, granted to NO operational role):** `view_legacy_rme_imports`, `create_legacy_rme_imports`, `review_legacy_rme_imports`, `publish_legacy_rme_imports`, `void_legacy_rme_imports` — Super Admin (the designated Master Data RME operator) holds them via the existing RoleSeeder `'*'` grant + the single global `Gate::before`; classified into the existing `rme` `PermissionGroupingService` group. Policies `LegacyRmeImportPolicy` (viewAny/view/create/review/publish/cancel) + `LegacyRmeRecordPolicy` (viewAny/view/void; **`update`/`delete` hard-wired `false`**) registered in `RepositoryServiceProvider::$policies` (`private`, not `protected` — copying stock Laravel registers nothing; there is no `AuthServiceProvider`). No policy `before()` hook (it would shadow the single global bypass). Branch isolation via `LegacyRmeWorkspaceScope` (governance tier = all RME-enabled branches, others pinned to `BranchContext::forUser`, **empty scope = deny-all**); **`origin_branch_id` is provenance metadata, never authorization**, and the branch is never read from the request. Repositories take the resolved branch-id list as the first parameter and fail closed (`whereRaw('1 = 0')`) on an empty scope.

**Audit:** reuses the shared `sys_audit_logs` trail through `AuditLogService` (no new audit table). `LegacyRmeAuditService` adds the payload policy the shared service lacks — every payload is filtered against `LegacyRmeAuditEvent::ALLOWED_METADATA_KEYS` and reduced to length-bounded scalars. Events `LEGACY_RME_IMPORT_CREATED`/`DATE_SELECTED`/`PUBLISH_REJECTED`/`DUPLICATE_DETECTED`/`PUBLISHED`/`VOIDED`. Never persisted: patient name, KTP/NIK, clinical content, base64, raw PDF, absolute path.

**Test-infra gotcha:** module models must declare `protected static function newFactory()` — Laravel otherwise resolves `Database\Factories\Modules\LegacyRme\Models\…Factory` and fails (all factories live in `database/factories/`, `Database\Factories\`). Tests: `tests/Feature/LegacyRme/{LegacyRmeSchemaTest,LegacyRmeFoundationTest,PatientEarliestNativeRmeDateResolverTest,LegacyRmeDateRuleServiceTest,LegacyRmePermissionTest,LegacyRmeNonRegressionTest}` (73). The suite is wired into the **CI critical filter** (`.github/workflows/foundation-evidence-gates.yml` — appended `|LegacyRme|PatientEarliestNativeRmeDateResolver`) because the CICD-CTRL-1 Selective Module Gate branches only on Inventory/Lab/Ui/Permission and `run_rme_tests` is consumed by no job. Deploy: `php artisan migrate --force` (4 additive tables) + `db:seed --class=PermissionSeeder --force` + `permission:cache-reset`; keep `FEATURE_RME_LEGACY_PDF_ARCHIVE` false. **Next: LEGACY-RME-PDF-1B** — upload runtime, page rendering, review UI, publish workflow, private-file serving, timeline integration and the doctor viewer, all behind the same flag.

## LEGACY-RME-PDF-1B — Private Upload Runtime, PDF Validation, Queue Processing & Page Rendering (2026-08-06)

Branch `feature/legacy-rme-pdf-1b-private-upload-rendering` (base `feature/sprint-26-phase-26-8-stabilization-closure-go-watch-no-go-report`, baseline LEGACY-RME-PDF-1A merge `0b37ce4` / GO tag `legacy-rme-pdf-1a-schema-permission-date-rules-go`; do NOT target main). Sprint doc `docs/sprints/legacy-rme-pdf-1b-private-upload-rendering.md`; ADR amendment in `docs/adr/0008-legacy-rme-pdf-archive-foundation.md`; rule mirror `.cursor/rules/90-legacy-rme-pdf-archive.mdc` (rules 21–35). Implements the intake runtime: **Super Admin → Master Data RME → Impor Arsip RME Lama → pick patient (Nomor RM) → choose the legacy date MANUALLY → upload PDF → validate → private storage → QUEUE → `pdfinfo` inspect → `pdftoppm` rasterize + thumbnails → page rows → `READY_FOR_REVIEW`.** **NO migration** (1A already shipped every column). **No new permission** — the five 1A permissions are the boundary. `FEATURE_RME_LEGACY_PDF_ARCHIVE` stays **false**.

**Deliberately NOT in 1B:** review approval, publish, promotion into `trx_rme_legacy_records`, patient timeline, doctor viewer, legacy print, annotation/pen/eraser/canvas, OCR, automatic date extraction, VOID runtime. **There is no publish route** (asserted by test). `READY_FOR_REVIEW` is the furthest a document goes.

**Private storage:** new disk `legacy_rme_private` (`driver local`, root `storage_path('app/legacy-rme-private')`, **`serve => false`**, `visibility private`, `throw true`). Rooted **outside** the `local` disk root on purpose: Laravel registers a `storage.{disk}` route for a local disk with `serve => true`, so anything under `storage/app/private` is in principle addressable by a signed framework URL — clinical pages must not be. `LegacyRmeStorageService::assertPrivateDisk()` refuses a disk that is forbidden/public/carries a `url`/has `serve` enabled. Paths are opaque: `rme-legacy/imports/p{patient_id}/{import_uuid}/{source,pages,thumbnails,processing}` — never a name/KTP/phone/diagnosis, and the uploaded filename is a sanitized display label only, never part of a path.

**PDF pipeline:** contracts `LegacyRmePdfInspectorInterface` → `PopplerLegacyRmePdfInspector`, `LegacyRmePdfRasterizerInterface` → `PopplerLegacyRmePdfRasterizer`, `LegacyRmeMalwareScannerInterface` → `ConfiguredLegacyRmeMalwareScanner` (OFF by default; when disabled it reports "not scanned", **never** "passed"), plus `Fake*` doubles so no test needs Poppler. `LegacyRmeProcessRunner` is the only place a binary runs — always an **argument array** through Symfony `Process` (execve, no shell), explicit timeout, binary from config; stderr/exit code go to the log only, never onto the exception (whose message is rendered AND persisted to `failure_message`). **Thumbnails use Poppler `-scale-to`, not GD/Imagick** — the local dev machine has no GD and an image dep would make rendering environment-dependent; they are PNG, and `getimagesize()` (core, no extension) validates pages. **`pdftoppm` zero-pads its suffix to the page-count width** (9 pages → `-1`, 10 → `-01`), so output is always discovered by scanning the dir and parsing the suffix — never by assuming a filename (real-Poppler test covers the 12-page case). Stable codes in `LegacyRmePdfFailure` (22 of them); callers branch on the **code**, never the message.

**Upload order:** feature flag → 1A date rules (never re-derived) → origin-branch validation → structural validation + server-side SHA-256 → duplicate precheck → malware scan → store private PDF → `DB::transaction` create staging row → **after commit** dispatch. The file is written before the transaction (a filesystem write cannot join one); a failed transaction deletes the orphan (tested). **The malware scan runs at upload, not in the job** — infected bytes are then never stored at all, and re-scanning immutable bytes on retry adds no security.

**Duplicate policy (server-computed SHA-256; filename irrelevant both ways):** PUBLISHED record → block (same or other patient); **VOID record → allow** (1A defines correction as "VOID plus a fresh import", so blocking would break the documented path — the collision is audited); active staging → block; FAILED same-patient → block and point at **Retry** (no second staging row); FAILED/CANCELLED **other** patient → allow (the mis-assignment fix must stay possible).

**Queue:** `ProcessLegacyRmePdfImport` extends ENT-5 `EnterpriseQueueJob`, `ShouldBeUnique`, queue `legacy-rme-documents`, carries **only the import id**. Status claim is one locked transaction (duplicate delivery = no-op); stale output + stale page rows cleared before rendering; pages upsert on `UNIQUE(legacy_import_id,page_number)`; temp dir removed in `finally`. **Queue retries do not drive domain failure** — a failure lands `FAILED` with a stable code and stops, and the operator's explicit Retry (`FAILED → QUEUED`, legal in the 1A map) is the recovery path; `failed()` covers a worker that died before recording anything. **No `READY_FOR_REVIEW → QUEUED` edge was invented** (nor `FAILED` abused to fake one) — a rendered document is corrected by cancelling and re-uploading. A stale `PROCESSING` (worker died) becomes reclaimable after 2× timeout + margin.

**HTTP:** 9 routes `settings.rme.legacy-imports.{index,create,store,show,status,source,pages.show,retry,cancel}` under `/settings/rme/legacy-imports`. **Deliberately NOT nested inside the `manage patients` group** — 1A defines the five legacy permissions as *the* boundary, and inheriting a second requirement would make them insufficient alone (a view-only holder opening the index is asserted). Three independent gates per action: route `permission:` middleware, controller feature-flag check (**disabled ⇒ 404**, so the surface reveals nothing), and the policy (per-row branch scope; new abilities `retry` + `viewFile`). `{import}` is a plain integer resolved through `findByIdInBranches()` with the caller's scope — **out-of-scope is 404, not 403**, so ids cannot be probed; a page is looked up **through** its import so a page number cannot cross imports. File responses: explicit Content-Type, `nosniff`, `Cache-Control: private, no-store`, generic download name (path and original filename never echoed).

**Security-review outcome:** two candidate findings were raised and both filtered to confidence 3 (below the ≥8 bar) — an equivalent, broader patient enumeration already ships via `settings/patients/{patient}/edit` (which even renders full KTP, for more roles), and the `origin_branch_id` issue is unreachable while only Super Admin holds the permission. **Both cheap fixes were applied anyway** because 1C will delegate these permissions: (1) `resolveOriginBranch()` now validates against the **uploader's own scope** and anchors a scoped operator's branchless upload to their own branch — the 1A claim that `origin_branch_id` is "provenance, never authorization" was **factually wrong** (repository listings filter on it, the policy scopes on it), and rule 14 has been corrected; (2) `assertPrivateDisk()` also refuses a disk with `serve` enabled; (3) patient selection by surrogate key goes through `LegacyRmePatientLookupService::findSelectable()`, applying the same doctor patient scope as the canonical Nomor-RM search, on **both** `create()` and `store()`.

**Test-infra:** new Pest helpers in `tests/Pest.php` — `legacyRmePdfBytes()` builds a structurally valid multi-page PDF in pure PHP (correct xref; no fixture binary committed, no clinical document used), `legacyRmePdfUpload()`, `legacyRmeNativeVisit()`, and `legacyRmeArchiveFlag()` (**the flag key contains a dot, so it is a literal array key — dot-notation config cannot reach it; the whole `feature_flags.flags` array must be rewritten**). Role-user HTTP tests need `withoutMiddleware(EnsureRmeOnlineContext::class)` (class lives in `App\Modules\RmeOnlineContext\Middleware`). `BranchContext` falls back to the first active RME-enabled branch, so branch-scope tests must pin `users.branch_id` explicitly or they pass for the wrong reason. **The 1A assertion "registers no HTTP route for the legacy RME archive" was replaced, not left to pass by accident** — its substring filters (`legacy-rme`/`legacy_rme`/`rme-legacy`) would not have matched the new `legacy-imports` naming, so it would have kept "passing" while the surface existed; it now asserts the exact staging route set **and** that `publish`/`review`/`approve`/`void` still have no endpoint.

**Config:** `config/legacy_rme.php` gains a `processing` block keeping the 1A `LEGACY_RME_*` env family (not a second `LEGACY_RME_PDF_*` family): `LEGACY_RME_DISK` (now `legacy_rme_private`), `_DPI` 180, `_THUMBNAIL_MAX_EDGE` 320, `_PROCESS_TIMEOUT` 180, `_MAX_PAGE_PIXELS` 40M, `_MAX_PAGE_DIMENSION_PT` 20000, `_MAX_RENDER_BYTES` 200MiB, `_QUEUE` `legacy-rme-documents`, `_TRIES` 3, `_MALWARE_SCAN` false. Tests: 7 suites, **179 passed / 551 assertions**; native RME regression 158 passed; permission/sidebar 42 passed. **Runtime dependency: `poppler-utils` (`pdfinfo`, `pdftoppm`)** on any host that processes documents; the real-Poppler suite **skips** (never silently passes) when absent. The `legacy-rme-documents` queue must be served by the managed worker before the flag is enabled. Deploy: **no migration, no seeder**. GO tag on merge: `legacy-rme-pdf-1b-private-upload-rendering-go`. **Next: LEGACY-RME-PDF-1C** — review approval, publish into `trx_rme_legacy_records`, patient-timeline integration, doctor viewer, legacy print.

## LEGACY-RME-PDF-1C — Controlled Publish & Patient History Integration (2026-08-10)

Branch `feature/legacy-rme-pdf-1c-controlled-publish-patient-history` (base `feature/sprint-26-phase-26-8-stabilization-closure-go-watch-no-go-report`, 1B merge `6b9ed7aa0e9971ea74adcc69e2e5f5e439c22d11`, GO tag `legacy-rme-pdf-1b-private-upload-rendering-go`; do NOT target main). Sprint doc `docs/sprints/legacy-rme-pdf-1c-controlled-publish-patient-history.md`; rule mirror `.cursor/rules/90-legacy-rme-pdf-archive.mdc` (rules 36–52). Closes the loop 1B stopped short of: a rendered import is reviewed by a human, published into an **immutable** legacy record, and appears in the patient's RME history behind a private read-only viewer. **NO migration** (1A already shipped every column and constraint, incl. `UNIQUE(source_import_id)` and the reviewed/published actor columns), **no seeder, no permission change** (the five 1A permissions are the boundary), no schema change; feature flag `rme.legacy_pdf_archive` stays **OFF** in production so the deploy is inert by construction.

**Flow (1A transition map NOT widened):** `READY_FOR_REVIEW → REVIEWED` (`POST settings/rme/legacy-imports/{import}/review`, `review_legacy_rme_imports`) → `REVIEWED → PUBLISHED` (`POST .../publish`, `publish_legacy_rme_imports`); `PUBLISHED` is terminal (no republish). Published viewer `GET rme/legacy-records/{record}[/source][/pages/{page}]` (`rme.legacy-records.*`, `view_legacy_rme_imports`) — GET-only, its own group under `/rme` (clinical, not Master Data), `permission:` applied INSIDE the `auth` group so a guest gets the login redirect rather than a 403.

**Key gotcha — `Gate::before` means a policy is not a boundary for Super Admin,** who is the only role holding these permissions. Every rule that must hold is enforced AGAIN in the service (status/date/pages/source) or the controller (VOID streaming, feature flag), and the tests assert each one *as a Super Admin*. New `LegacyRmePublishService`: one `DB::transaction` opened with `lockForUpdate`, status re-read under the lock, idempotent via `findBySourceImportId` short-circuit, with `UNIQUE(source_import_id)` as the independent DB defence; 1A date rules **re-validated at publish time** against a freshly resolved cutoff (the intake snapshot is evidence, never authority); refuses an incomplete archive with stable path-free codes (`RENDERED_PAGES_MISSING`/`PAGE_COUNT_MISMATCH`/`PAGE_FILE_MISSING`/`SOURCE_FILE_MISSING`/`IMPORT_NOT_PUBLISHABLE`/`IMPORT_NOT_REVIEWABLE`). **Second gotcha — a refusal audit written INSIDE the failing transaction is rolled back with it**; new `LegacyRmePublishRefusal` carries the field + PII-free metadata out of the transaction and is converted to a `ValidationException` at the boundary (it must never escape as a 500 — that bug was caught in review for the `review()` path too). Publishing **promotes metadata and moves no bytes** (1B's private per-import directory is already final), so a rolled-back publish cannot orphan a file.

**Patient history:** new read-only `LegacyRmePatientHistoryService` merges the caller's already-resolved native visit history with the patient's **PUBLISHED** legacy records into `LegacyRmeTimelineEntry` rows, ordered by the **clinical** date (`rme_date` / `visit_date`, never upload time) with a deterministic tie-break. Legacy and native stay separate entities — publishing creates no `ClinicVisit`/`MedicalRecord`/invoice/payment/consent/odontogram/lab candidate/order/SATUSEHAT candidate and never changes a visit status (asserted by count-before/after tests). The native side is passed in from `ClinicVisitController::show()` rather than re-queried (no second definition of "the patient's visits"); the merged card renders **nothing** when the flag is off, the permission is missing, or the patient has no archive — so the RME workspace is unchanged from before this sprint.

**Security decisions (from an explicit review — no CRITICAL/HIGH found):** a **VOIDed archive stops streaming its bytes** (404 in the controller, not just the policy) because VOID exists for a mis-filed archive, canonically one attached to the WRONG patient; the row stays readable (retracted, not erased). `LegacyRmeImportPageStatus::VIEWABLE` is deliberately wider than `PUBLISHABLE` so a published import's staging pages stay viewable as review evidence. Streaming honours the **disk stored on the row** (`diskFor()` re-asserts it is private) so repointing the configured disk cannot silently 404 history. `PublishLegacyRmeImportRequest::prepareForValidation()` 404s when the flag is off so a malformed payload cannot answer 422 and confirm the endpoint exists. Gallery thumbnails are not audited (opening the archive already writes `RECORD_VIEWED`). Review is a mandatory **state** gate, **not** four-eyes — `publish()` deliberately allows the same actor, since only Super Admin holds either permission; enforce separation of duties in the service and split the roles if that changes.

**Tests:** new `LegacyRmePublishTest`, `LegacyRmePatientHistoryTest`, `LegacyRmeRecordViewerTest`. Repinned two superseded 1B assertions (same pattern every prior sprint used): `LegacyRmeNonRegressionTest` "no review/publish endpoint" → "exactly the staging surface plus review and publish" (+ a new GET-only assertion for the viewer), and `LegacyRmeImportAuthorizationTest` "publish route does not exist" → "no publish action offered on an unreviewed import". **PostgreSQL gotcha:** a unique violation aborts the surrounding `RefreshDatabase` transaction (`SQLSTATE[25P02]`), so the constraint assertion runs inside a nested transaction (SAVEPOINT) and behaves identically on SQLite and PG. Green: LegacyRme 237 (SQLite **and** PostgreSQL 16.14, matching production), `tests/Feature/RME` 1031, RME critical regressions, real Poppler executes (never silently skips), pint repo-wide + `git diff --check` clean. Deploy: no migration/seed; keep `FEATURE_RME_LEGACY_PDF_ARCHIVE=false`; rollback `scripts/rollback-vps.sh legacy-rme-pdf-1b-private-upload-rendering-go`.

**Governance metadata closure (post-merge, inert):** the `rme.legacy_pdf_archive` entry in `config/feature_flags.php` still described the 1A foundation — description "upload/publish runtime lands in a follow-up sprint", `rollout_status: foundation`, `review_target: LEGACY-RME-PDF-1B`, and a rollback action claiming "nothing is imported or published". All four statements were falsified by shipped 1B and 1C runtime, so the flag was realigned to `rollout_status: implemented` / `review_target: LEGACY-RME-PDF-1C`, a description covering 1A+1B+1C, and a rollback action stating that data **persists** (schema, staging rows, published records and their private files) and only the runtime becomes inaccessible. Same convention as `satusehat.integration_readiness` / `satusehat.external_submission_enabled`: **`implemented` marks that the runtime exists, never that production exposure is on** — `default` stays `false`, `risk_level` stays `high`, `env_key` is unchanged, and `rollout_status` is free-form metadata (no enum, no validator) consumed only by `FeatureFlagService::hydrate()`, `foundation:feature-flags` and `PostgresRuntimeGovernanceService` reporting. **Known trap, deliberately NOT changed here:** this flag has no `env_value => env(...)` capture, so under a config-cached deploy a runtime `FEATURE_RME_LEGACY_PDF_ARCHIVE=true` is ignored and the flag resolves to its `false` default — fail-closed today, but the SATUSEHAT flags show that capture is required before any controlled-rollout sprint can actually enable this in production.

Scope binding (not merely a non-empty string) is deliberate: a reference alone proves only that *some* approval exists, so adding a fourth branch to a three-branch wave would silently inherit the older narrower decision — instead the new branch fails closed while approved ones keep working. **ROLL-2's `pilot_scope` is immutable historical evidence and authorizes nothing in ROLL-3**; the admission gate never consults it, so the historical TKM1 approval cannot stretch to a later wave, and pasting that reference still fails unless its approved scope contains the admitted branches. *Why this exists:* at the Wave-1 checkpoint production carried `ROLL-2-OWNER-APPROVAL-2026-08-11`/`TKM1` while `ATG3`/`LDK2`/`SUN4` were about to be admitted — enforcement would have been correct but the gate would have printed **GO** beside an approval naming a branch outside the wave, i.e. the ROLL-3 defect recurring one level up.

**NORMAL DRAIN vs EMERGENCY STOP — two distinct operational controls, never interchangeable.** *DRAIN* (remove a branch code + rebuild config cache) stops **new ingestion only** — upload/create and retry re-queue — for that branch; imports already staged and human-reviewed keep their lifecycle and may still be published, with publish running the full canonical revalidation (permission, patient, RM-derived branch, date range, native boundary, state machine). **What it adds.** ROLL-3 answered *"may this BRANCH migrate?"*. **THE COMPOSITION RULE — the whole safety argument: ROLL-4 CAN ONLY NARROW, NEVER WIDEN.** Ingestion order is `capability → date rules → RM-derived branch → ROLL-3 admission → ROLL-3 capacity → ROLL-4 operations gate → storage → transaction(quota reserve + staging row) → after-commit dispatch`. **Quota.** Counting point = **accepted into staging**, reserved inside the same transaction as the staging row, so a rolled-back import releases its quota with no compensating write. **Retries are NOT charged again** (the document was already accepted; render load is ROLL-3's capacity gate). Branch completion requires zero in-flight, zero unresolved failures, zero unexplained, zero drift, status `DRAINING`, and a sign-off note; the reconciliation is **recomputed under the row lock** and frozen onto the row. Wave completion requires every enrolled branch `COMPLETED` or explicitly `CANCELLED`. **An empty queue is never completion, and `failed_jobs = 0` is never queue-health evidence** (the ROLL-2 lesson).

## LEGACY-RME-OPS-CLI-1 — Canonical Import Lifecycle CLI & Abort-Recovery Operations (2026-08-16)

Branch `feature/legacy-rme-ops-cli-1-canonical-import-lifecycle-cli-abort-recovery` (base `feature/sprint-26-phase-26-8-stabilization-closure-go-watch-no-go-report` @ `eb96dae`; do NOT target main). Sprint doc `docs/sprints/legacy-rme-ops-cli-1-canonical-import-lifecycle-cli.md`; runbook §16 of `docs/runbooks/legacy-rme-migration-operations-runbook.md`; rule mirror `.cursor/rules/101-legacy-rme-import-lifecycle-cli.mdc`; manifest `.sprint/current.yml` (MODULE_SPRINT). **No migration, no new permission, no new route, no seeder/role change, no schema change; the observable HTTP contract is unchanged (404 out-of-scope, 403 refused, field errors on service refusal).**

**Why:** Wave-2 was opened against live clinical data and aborted, and the operator could not canonically withdraw or progress the staged imports over SSH — `cancel`/`review`/`publish`/`retry` existed **only** as controller methods. The alternatives an operator reaches for (direct `UPDATE`, Tinker `->update(['status'=>…])`, hand-edited `published_by`, manual quota adjustment) bypass the transition map, branch scope, policy, quota semantics **and** audit trail at once.

**Architecture — one business path, two adapters.** New `LegacyRmeImportLifecycleService` is the ONLY implementation of the gates; **both** `LegacyRmeImportController` and the new `legacy-rme:import-admin` command enter through it, and it delegates every state change to the unchanged canonical services (`LegacyRmeImportProcessingService` retry/cancel, `LegacyRmePublishService` review/publish). The controller no longer calls `$this->processing->`/`$this->publishing->` at all — **asserted structurally by a test**, so a future direct call fails CI. Gate order, each failing closed: **(1)** feature flag → `FEATURE_DISABLED` (a recovery tool that worked while the emergency stop was pressed would BE the bypass); **(2)** branch scope via `LegacyRmeWorkspaceScope` → `IMPORT_NOT_IN_SCOPE` (fires BEFORE permission on purpose — "not found" and "not yours" are deliberately the same answer so id probing cannot reveal another branch's staged documents); **(3)** the named permission the HTTP **route** declares as middleware → `PERMISSION_DENIED`; **(4)** `LegacyRmeImportPolicy` → `POLICY_DENIED`; **(5)** separation of duties → `SEPARATION_OF_DUTIES`; **(6)** canonical service → `SERVICE_REFUSED`. New Support types: `LegacyRmeLifecycleAction` (closed vocabulary + the route-permission table both surfaces read), `LegacyRmeLifecycleRefusal` (stable machine-readable codes), `LegacyRmeLifecycleOutcome` (PII-minimized result), `LegacyRmeImportNotInScope` (**extends `NotFoundHttpException`** so the browser's long-standing 404 is byte-identical while the CLI reports a branchable code), `LegacyRmeLifecycleDenied` (extends `AuthorizationException`, still 403, but remembers WHICH gate refused), `LegacyRmeCommandRefusal`.

**CLI:** `php artisan legacy-rme:import-admin {cancel|review|publish|retry} --import=<id> --actor=<id|email> [--title= --description=] [--apply] [--json]`. **Safe by default three ways:** one import per invocation (**no `--all`/`--branch`/`--wave`/`--force`** — asserted by a test); **dry run unless `--apply`** (zero row/audit/job delta, asserted by counting); an **explicit, real, ACTIVE, non-soft-deleted** `--actor` (the Linux user, the SSH login and root are never an application identity). Exit `0` only when the requested outcome was reached or a dry run found the action eligible; **every refusal exits non-zero**, including an ineligible dry run.

**Gotchas found by running, not reading.** (1) **`LegacyRmeAuditService` had to become a container singleton** (`RepositoryServiceProvider::register`) — the channel tag is set by the lifecycle service but audit rows are written by the canonical services from their **own injected copy**, so without a shared instance every row silently lost the tag; state is scoped by `withChannel()` and restored in a `finally` so a long-lived queue worker cannot inherit a stale value. (2) **`Exception::$code` cannot be redeclared readonly** — the refusal types carry `refusalCode`. (3) **A dry run must consult the transition map DIRECTLY**, not just the policy: a Super Admin's global `Gate::before` makes every policy answer yes, so the policy predicts nothing for the account most likely to be running a 2am recovery; `TRANSITION_NOT_ALLOWED` exists solely so `preview()` cannot lie, and `perform()` deliberately does NOT duplicate it (the canonical services own that rule). (4) **A Kasir is refused by the SCOPE gate, not the permission gate** — and tests must pin `users.branch_id` explicitly, because `BranchContext` otherwise falls back to the first active RME-enabled branch and can coincidentally BE the import's branch, passing for the wrong reason. (5) Test fixtures needed **per-call-unique PDF bytes** (vary the page width) — the shared helper emits byte-identical PDFs and the archive correctly refuses an identical checksum staged against a different patient.

**Semantics preserved verbatim (each pinned by a test):** cancelling **does NOT refund quota** (the bucket is a reservation spent at intake; a refund would let an operator loop `upload → cancel → upload` past the approved ceiling); **review is a real gate** — an unreviewed import cannot be published, by the policy for a checker AND by the canonical service for a Super Admin whose `Gate::before` bypasses the policy (both paths tested); **publish is idempotent, never duplicating** (a repeat returns the existing record with `changed:false`; `UNIQUE(source_import_id)` is the DB backstop); **retry means requeue, not reset** (`PUBLISHED`/`CANCELLED` terminal and refused; a retry whose source PDF is gone is refused with a reason); **no downstream state ever** — no `ClinicVisit`/`MedicalRecord`/odontogram/invoice/payment/`LabOrder`/SATUSEHAT candidate from any action on either surface, asserted per action including refusal paths.

**Separation of duties — recorded honestly.** `imported_by != published_by` was **NOT** enforced in code before this sprint. What actually enforces maker/checker is the **ROLE SPLIT** (maker holds `create_legacy_rme_imports`, denied `review`/`publish`; checker holds `review`+`publish`, denied `create`) — unchanged and still load-bearing. New `legacy_rme_operations.require_separate_publisher` (env `LEGACY_RME_REQUIRE_SEPARATE_PUBLISHER`) adds the account-level check, **default OFF**, mirroring `require_separate_approver` including its "turn on once two staffed accounts exist" posture; it lives in the **shared** lifecycle service so browser and CLI tighten together — deliberately no way to have it on one surface only (tested on both). Pre-attribution rows (`uploaded_by IS NULL`) stay exempt.

**Config default flipped ON, fail-closed.** `(bool) env(..., false)` → `SeparatePublisherGuard::resolveEnabledFromEnv(env(...))`. The failure mode that matters is a **typo**, not a deliberate `false`: `env()` returns null for a misspelled key and `''` for a valueless key, and PHP casts both to false, so `LEGACY_RME_REQUIRE_SEPARATE_PUBLISHR=true` would have silently disabled a production safety invariant. **Account SOD ≠ human SOD — never blurred in evidence.** The server enforces `imported_by_user_id != acting_user_id` and proves two ACCOUNTS touched the document. It CANNOT prove two HUMANS hold them; no identity mechanism here establishes that. Two people sharing one login therefore cannot satisfy the rule (desirable — shared accounts destroy accountability); one person with two logins can, which is why controlled migration operations still require genuinely separate human operators as an operational governance control with a human attestation.
