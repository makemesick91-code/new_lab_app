5. **QC**: gagal wajib alasan + target rework eksplisit (default STEP_2); rework membuka kembali step target..4 + reaktivasi assignment; nomor revisi dari hitungan log QC_FAILED. **SEGREGATION OF DUTY**: teknisi produsen tidak boleh pass/fail QC-nya sendiri (baru di V2, tidak ada di legacy).
6. **Delivery proof (aturan owner, 3 lapis server-side)**: sebelum IN_TRANSIT_TO_BRANCH wajib foto serah terima lab→kurir + TTD kurir; DELIVERED wajib nama + TTD penerima + foto lokasi/bukti. FormRequest keduanya/ketiganya required + service simpan atomik & re-assert + matrix tanpa edge bypass. Disabled button bukan security.
7. **Bukti privat bertipe** `trx_lab_workflow_evidence` (7 tipe eksplisit, sha256, soft-delete only — bukti audit tidak boleh hard-delete) di disk privat `local`; serve hanya via `lab-workflow-evidence.show` + `LabWorkflowEvidencePolicy` (lab/kurir semua; aktor cabang = cabangnya). Signature = file PNG divalidasi magic bytes (bukan base64 di DB). Validasi bytes riil `getimagesizefromstring` (anti MIME-spoof).
8. **Branch**: transisi aktor-cabang saja yang branch-equality-scoped (`branch_scoped_transitions`); kurir/lab lintas-cabang by design, dijaga kepemilikan task. Workspace cabang selalu `BranchContext` — jangan percaya branch_id request.
9. **Notifikasi = in-app database notifications saja** (`LabWorkflowNotificationService`, halaman `/notifications`, self-scoped) — TIDAK ada auto-WhatsApp; kegagalan notifikasi di-log dan tidak pernah membatalkan transisi.
10. **RME → LabCaseCandidate → convert tetap manual review**; saat V2 aktif konversi menghasilkan order V2 DRAFT (`createV2Draft`); kegagalan lab TIDAK me-rollback payment RME.
11. Report produksi legacy membaca `trx_lab_order_assignments.status='DONE'` — semantik status assignment V2 dipertahankan identik. Permissions baru hanya Phase 2: `create_lab_branch_requests` (Perawat/Admin Klinik/Admin Lab), `manage_lab_pickups` (Courier/Admin Lab).
12. **Test-infra**: CLI lokal tanpa GD — pakai `fakeEvidencePhoto()` (PNG bytes riil) di `tests/Pest.php`, JANGAN `UploadedFile::fake()->image()`. Suite: `tests/Feature/LabWorkflow/` (foundation/branch-request/pickup/analysis-production/external/delivery-proof).

Sprint doc `docs/sprints/fix-lab-analytics-median-lateness-day-boundary-1.md`; rule mirror `.cursor/rules/124-time-dependent-test-determinism.mdc`. Closes the time-of-day flake FIX-PDF-TEMPFILE-LEAK-1 recorded as known-and-deferred. **No migration, no permission, no route, no runtime application change — `RUNTIME_APPLICATION_FILES_CHANGED=0`, `RUNTIME_BEHAVIOR_CHANGE=false`.**

**Root cause — test fixture, not runtime.** `LabOperationalAnalyticsMetricTest` pinned the deadline to a calendar date (`due_date => now()->subDays(2)->toDateString()`) but the delivery to a wall-clock instant (`opLog($late, DELIVERED, now())`). `slaCompliance()` measures lateness as an **elapsed duration from the END of the due day** (`round($due->diffInMinutes($delivered)/1440, 2)`), so those records were `1.00` days late just after midnight and `2.00` just before it. Against `toBeGreaterThan(1.0)` the verdict was decided by the runner's start time. The metric itself is deterministic given its inputs — only the inputs were not.

**Failure window pinned to the second: `[00:00:00, 00:07:11]`** in the application timezone (7m12s/day, ~0.5% of runs), reproduced by binary search under a controlled clock — never by waiting for midnight and never by rerunning CI. `00:07:11` → `1.0` FAIL, `00:07:12` → `1.01` PASS. **This refines the earlier "00:07+ pass" estimate**, which was one minute optimistic: the edge is arithmetic (`raw ≥ 1.005` needs `≥ 432s` past midnight). Base-authority control: 1 failure at `00:02:59` (the reported CI instant), **2** at `2026-06-01 00:05:00`, 0 at midday — the midday green is what hid it.

**Time authority (`LAB_ANALYTICS_TIME_AUTHORITY = APPLICATION_TIMEZONE`, UTC), established from code not from CI's clock.** `resolvePeriod()` uses `today()`, `slaCompliance()` uses `Carbon::parse(...)->endOfDay()`, `config/app.php` hardcodes `'timezone' => 'UTC'`, and Graphify found no `ClinicalClock` edge in the `LabOrder` module. **`ClinicalClock` (Asia/Makassar) was deliberately NOT borrowed** — it is the *clinical*-date authority and nothing here is clinical. Pinned behaviourally by a case frozen at `16:00Z` (WITA midnight) asserting the window still ends on the UTC date.

**The false fix was rejected with evidence, not opinion.** Widening `>` to `>=` goes green without touching the defect: with the runtime mutated to return a **mean** instead of a median, the weakened assertion passes **12/12** while the new boundary suite fails **10/14**.

**Fix.** `tests/Pest.php` gains canonical `pinTestClock()` / `freeTestClock()` (application-timezone reference clock; small and shared — no system-wide temporal framework). The SLA case is pinned *at the instant it used to fail* (`2026-05-15 00:02:59`) **and** its delivery is anchored to its own due day (`$dueDay->addDays(3)->startOfDay()` → exactly `2.00` days late), so the expectation is exact (`toBe(2.0)`) and intrinsic to the fixture rather than to the chosen instant. New `LabOperationalAnalyticsDayBoundaryTest` (14) asserts **invariance** across the boundary (both window edges + the reported failure instant + WITA midnight), true median semantics (1/2/4 → `2.0`, not the `2.33` mean), the even-count convention (1/4 → `2.5`), "the due day itself is never late", the timezone authority, and no leaked clock.

**Same-class sibling found and fixed:** the QC first-pass test placed its first attempt `subMinutes(10)` before a live `now()` inside a **calendar-month** window, so during the first 10 minutes of every 1st the failed attempt fell out of period and the test silently became a 2/2 first-pass assertion (reproduced at `2026-06-01 00:05:00`). Siblings **audited and cleared** from the repository's actual filter columns: throughput, external turnaround (filters `returned_at`) and technician KPI (assignments never period-filtered) move both endpoints together and are duration-stable.

**Honest negative:** the "remove the `afterEach` clock release" mutation did **NOT** fail — Laravel's `InteractsWithTestCaseLifecycle::tearDownTheTestEnvironment()` already calls `Carbon::setTestNow()`, so the framework guarantees the reset and the leak guard cannot observe that removal. The explicit release is kept as documented pairing/redundancy, not claimed as what the guard proves.
