## LEGACY-RME-SOURCE-RM-BINDING-1 — Source RM Capture, Patient-Binding Enforcement & Wrong-Patient Prevention (2026-08-17)

Branch `feature/legacy-rme-source-rm-binding-1-source-rm-capture-patient-binding-enforcement` (base `feature/sprint-26-phase-26-8-stabilization-closure-go-watch-no-go-report`, baseline MASTERDATA-1 GO `431d5af`; do NOT target main). Doc `docs/sprints/legacy-rme-source-rm-binding-1-source-rm-capture-patient-binding-enforcement.md`; rule mirror `.cursor/rules/90-legacy-rme-pdf-archive.mdc` §65–79 (§63's product gap is marked CLOSED); operator runbook `docs/runbooks/legacy-rme-migration-operations-runbook.md` §14a; manifest `.sprint/current.yml` (MODULE_SPRINT). **Closes the binding-integrity product gap MASTERDATA-1 recorded.** ROLL-4-WAVE-2 stays CLOSED/IMMUTABLE; **ROLL-4-WAVE-3 stays SKIPPED / NOT REQUIRED** (no wave created, no approval, no quota, no GO tag); RM 27541 stays `DOCUMENT_NOT_ELIGIBLE` and is used only as a negative regression; SOD `LEGACY_RME_REQUIRE_SEPARATE_PUBLISHER=true` preserved; production stays `CAPABILITY=OFF / ADMISSION=EMPTY / ACTIVE_WAVE=NONE`. **No permission, no role/seeder change, no route.**

**The failure being removed.** Wave-2 produced a real wrong-patient binding: an operator selected one patient and uploaded a document belonging to another, and the write path could not tell, because the Nomor RM printed on the paper was never captured — there was no independent assertion to compare the selection against. It surfaced later from a frozen source hash and manual evidence.

**Migration (additive only, `migrate`, never `migrate:fresh`/`db:wipe`):** `2026_08_17_100001_add_source_rm_to_legacy_rme_tables` adds nullable indexed `source_rm_raw` / `source_rm_normalized` / `source_rm_resolution` to `stg_rme_legacy_imports` and `source_rm_raw` / `source_rm_normalized` to `trx_rme_legacy_records` (carried onto the immutable record beside `source_pdf_sha256`, so an audit can answer "what patient did this document claim?" without joining the soft-deleted staging row). **Nullable is for HISTORY ONLY and nothing is backfilled** — copying the selected patient's RM onto old rows would convert a derived assumption into false source evidence.

**Canonical chain:** human-confirmed source RM → `LegacyRmeSourceRmNormalizer` → `LegacyRmePatientResolutionAuditService::resolveIdentity()` → exactly one patient → compare with the SELECTED patient → asserted-branch-segment check. New `LegacyRmeSourcePatientBindingService` is **the** rule (writes nothing, takes **no actor** — whether a document is about a patient cannot depend on who is asking); `LegacyRmeSourceRmBinding` + `LegacyRmeSourceRmFailure` carry the immutable result and the stable codes `SOURCE_RM_REQUIRED` / `_INVALID` / `_NOT_FOUND` / `_AMBIGUOUS` / `_PATIENT_MISMATCH` / `_BRANCH_MISMATCH` / `_CAPTURE_MISSING`. **Identity reuse, not duplication:** `resolveIdentity()` was extracted from MASTERDATA-1's `resolve()` so both share one private `identify()` — same matching, minus the near-miss scan, which is both too expensive for a write path and something a component deciding identity must never be able to see. **Normalization repairs transcription and never moves a digit** (outer whitespace, whitespace hugging a separator, Unicode dash variants; a parseable value is rebuilt through `PatientMedicalRecordNumberService::compose()`, the documented inverse of `parse()`, so the manual sequence is carried verbatim and only the prefix/branch-code are re-cased).

**Enforcement.** The gate runs **FIRST** in `LegacyRmeImportService::createFromUpload()` — before dates, branch derivation, admission, capacity, the operations gate, hashing, file storage and the in-transaction quota reservation — so a refused wrong-patient binding leaves **no staging row, no stored file, no queued job and quota delta 0**. Also on **retry** (`assertRetryAdmitted`) and, under the row lock, in `LegacyRmePublishService::review()` (before the re-review no-op shortcut, since review CERTIFIES) and `publish()` (beside the existing date/branch revalidation — date, branch and identity are the three facts a permanent record freezes, and all three are re-derived rather than trusted from staging time). **CANCEL is never gated** — every "cancel and re-import" instruction is a lie if cancel is blocked by the same refusal that produced it. Because the rule lives in the SERVICE, HTTP, a direct service call and `legacy-rme:import-admin` are the same door (pinned by a direct-service test and a CLI publish test); `StoreLegacyRmeImportRequest` validates SHAPE only.

**Design correction found by running the suite, not by reading it.** The guard originally re-resolved the archive's owning branch, which duplicated FIX-ROLL2-1 and — because the guard runs first — swallowed `LegacyRmeBranchResolver`'s specific refusals ("inactive", "not RME-enabled", "out of scope") behind a generic identity error, telling an operator to re-read a document when the real fix was master data. It now compares only the branch segment the DOCUMENT asserts against the patient's own (pure parsing, no query). `LegacyRmeBranchResolver` remains the sole owner of the owning branch.

**Non-disclosure.** A refusal never names the patient a rejected Nomor RM actually belongs to — no id, no name, no RM, in the message or the audit payload. The upload form is reachable by any `create_legacy_rme_imports` holder, so a helpful refusal would be a patient-enumeration oracle. New audit action `LEGACY_RME_SOURCE_RM_BINDING_REJECTED` (its own action: a wrong-patient refusal is operationally distinct from a branch, rollout or throttle refusal) with allow-listed keys `source_rm_normalized` + `source_rm_resolution` only — the NORMALIZED value, never the raw operator transcription (free text has been excluded from this allow-list since 1D).

**Pre-enforcement rows.** Terminal rows (PUBLISHED/CANCELLED/VOID) untouched — Wave-2R history renders unchanged. Non-terminal rows are refused at review/publish/retry with `SOURCE_RM_CAPTURE_MISSING` telling the operator to cancel and re-import. Production's resting state has none, so it is a safety net, not a migration task.

**UI.** Required "Nomor RM pada Dokumen" + its own attestation ("Saya memastikan nomor RM yang dimasukkan sesuai dengan nomor RM yang tercetak pada dokumen RME Legacy."), **deliberately NOT prefilled** from the selected patient and with no "copy from patient" helper — a value that agrees with the selection by construction cannot catch a wrong selection. Review screen shows the asserted RM beside the patient's own.

**Production proof without manufacturing data.** New read-only `php artisan legacy-rme:source-rm-binding-check --source-rm= --patient= [--normalize-only] [--json]` calls the same guard object the write path calls, creates nothing, needs no wave/admitted branch/enabled capability, and exits 1 on refusal — so the wrong-patient probe is EXPECTED to fail and an exit 0 there is the alarm. `LIVE_MUTATION=NOT_EXERCISED` by design; no migration wave is opened for smoke evidence.

**Compatibility.** `createFromUpload()` gained a **required** `$sourceRm` at position 3 — required and early on purpose, so adding a mandatory identity assertion breaks every caller loudly instead of defaulting silently (47 test call sites updated). `LegacyRmeImportFactory` stamps a coherent binding by default (a fixture builds the row a correct confirmation WOULD produce — that is not the forbidden production backfill), with `->withoutSourceRm()` for a genuine pre-enforcement row and `->sourceRm()` for a deliberately wrong one.

**Durable rules (mirror §65–79):** every new import captures the printed Nomor RM as structured data · the source RM is independent of the selected patient and is never prefilled/auto-copied · filename is never source-RM authority (`source_pdf_sha256` identifies the DOCUMENT, the source RM identifies the asserted PATIENT) · OCR is assistive only and never becomes authority without human confirmation · normalization never changes a digit · identity is EXACT and fuzzy matching is unreachable from the write path · every failure code fails closed with no override · the gate runs before queue/review and before quota · the rule lives in the service so HTTP/CLI/direct-call are one door · the source RM does not decide the owning branch (FIX-ROLL2-1 still does) and request `branch_id` is never an authority · the source RM is immutable after acceptance (correction = cancel + re-import) · the binding is revalidated at review/publish/retry · cancel is never gated · pre-enforcement rows are never given a manufactured source RM · a refusal never discloses whose Nomor RM it is.

Tests: new `tests/Feature/LegacyRme/LegacyRmeSourceRmBindingTest.php` (41) — normalization incl. the 27541 pair, the full binding matrix, zero-footprint on refusal (`Bus::assertNothingDispatched`), HTTP + direct-service + CLI parity, audit shape and non-disclosure, review/publish/retry revalidation, pre-enforcement refusal, cancel availability, bounded query count, and the archive boundary (no visit/MR/invoice/payment/lab/SATUSEHAT state). Deploy note: `php artisan migrate --force` (1 additive migration); **no seed, no permission change**; keep the capability flag OFF.

**Durable rules (mirror rule 103):** legacy RME migration is routine operations, not a sprint per batch · a routine batch IS the existing ROLL-4 wave record (never a new table/state machine — a second path to the same clinical writes would be weaker) · **`ROLL-4-WAVE-3` stays SKIPPED / NOT REQUIRED and is now also REFUSED as a declared batch code** · every batch needs a FRESH approval (Wave-1/Wave-2R approvals are immutable evidence, never reused) · resting state = capability OFF + admission EMPTY + active batch NONE · **a routine batch never earns a GO tag** · no verified backup <24h ⇒ no batch (refusal, not warning) · closure needs zero in-flight/unexplained/quota-drift/unresolved-failures + written sign-off, no `--force` · a cancelled import still consumes quota · archive-only permanently (any native clinical/billing/lab/SATUSEHAT side effect is stop-the-line) · never SQL/Tinker for lifecycle state · never a shared maker/checker account.

**`MULTI_BRANCH_MODE = CONCURRENT_BRANCH_ISOLATED_WITHIN_ONE_ACTIVE_BATCH`** — read from the code, not aspirational: **across batches SEQUENTIAL** (`LegacyRmeWaveBindingService` resolves the operative batch from ONE declared code; concurrent batches unsupported and deliberately NOT added), **within one batch CONCURRENT + branch-isolated** (`ops_rme_legacy_wave_branches` carries per-branch status/quota/operators/transitions).

**Sizing derived, not invented:** `default_daily=25` is the ingestion queue's own single-worker pending ceiling (`capacity.max_pending_jobs` — beyond it uploads are already refused by backpressure, so a bigger allowance cannot make documents flow faster); `max_daily=100` is 4× that, bounded by human review throughput; above 100 is not routine (elevated approval); absolute rail stays the server-side `max_declarable_daily=500`. **MEASURED THROUGHPUT IS NOT AVAILABLE** — production evidence is Wave-1 (1 doc) + Wave-2R (4 docs) = five documents, far too small to fit a rate to. Bounded defaults for recoverability; never quote as a benchmark.

**Design decisions worth keeping:** backup freshness **reuses** the MON-1 signal rather than re-probing (a second "is the backup fresh?" implementation would be free to disagree with the first) · monitoring signals are collected **BY DEFAULT** — the first cut gated them behind `--include-monitoring`, which made the *default* invocation permanently NO_GO; `--skip-monitoring` now opts out and degrades honestly · **"not established" ≠ "stale"**: both block, but only a genuinely missing/stale backup is stop-the-line (`BACKUP_NOT_ESTABLISHED` vs `BACKUP_MISSING_OR_STALE`) — reporting "I did not look" as a failed control trains operators to ignore the loudest signal · the batch **naming pattern is advisory and deliberately NOT asserted** (a check would fire permanently against the legitimate historical `WAVE-1`/`WAVE-2R`) while **`WAVE-3` IS asserted** (a retired identity has no approval record and no historical rows to false-positive against) · a deliberately closed branch is `NOT_READY` with **zero blockers**, not a fault · `UNKNOWN` blocks exactly like `FAIL` · **human SOD is attested, never asserted** — the report carries `human_separation_verifiable_by_application: false` rather than implying it verified two humans · `require_separate_approver` deliberately left OFF (one staffed governance account) and reported as WARNING, never flipped.

**Architectural guard tripped and honoured (worth remembering).** The first implementation read `config('legacy_rme_operations.require_separate_publisher')` directly and `LegacyRmeSeparationOfDutiesTest > it gives the enablement switch exactly one home in the application` failed — that test scans `app/` for the literal and asserts `SeparatePublisherGuard` is its only reader, because a second reader *decides for itself* whether the rule applies. Fixed by asking `SeparatePublisherGuard::enabled()` and renaming the report key to `separate_publisher_enforced`. **The guard was right and the new code was wrong.** Any future LegacyRme work must read SOD through the guard, never its config key.

**`LIVE_ROUTINE_BATCH = NOT_EXERCISED`** — no genuine owner-authorized candidate set existed during this sprint; no patient/document/hash/approval/batch was fabricated to manufacture a green line. Verification is automated tests + read-only production checks + safe drills.

## LEGACY-RME-DOCTOR-WORKSPACE-1A — Inline Legacy PDF Pages in the Handwritten RME Swipe Canvas (2026-08-18)

Branch `feature/legacy-rme-doctor-workspace-1a-inline-legacy-pdf-swipe` (base `feature/sprint-26-phase-26-8-stabilization-closure-go-watch-no-go-report`, BASE_SHA `f47735ac`; do NOT target main). Sprint doc `docs/sprints/legacy-rme-doctor-workspace-1a-inline-legacy-pdf-swipe.md`; rule mirror `.cursor/rules/92-legacy-rme-inline-workspace-pages.mdc`; doctor guidance = §14 of `docs/runbooks/legacy-rme-pdf-rollout-runbook.md`; manifest `.sprint/current.yml` (MODULE_SPRINT). **Corrective/product-completion sprint.** LEGACY-RME-DOCTOR-WORKSPACE-1 was technically correct but did NOT implement the owner's intended UX: a doctor still had to leave the `RME Tulisan Tangan Lengkap` page navigation, pick a document from the top rail and enter a second viewer with its own internal paging. **1A changes presentation/navigation ONLY — never legacy clinical persistence.**

**Product rule: ONE PAGE NAVIGATION EXPERIENCE, TWO DATA SOURCES** — native handwritten page = editable, legacy PDF page = read-only. Native pages and legacy archive pages now form ONE numbered sequence behind the same `?rm_page=` index, the same `← Sebelumnya`/`Berikutnya →` buttons, the same numbered buttons and the same swipe zone. A legacy PDF with N pages contributes **N** virtual workspace pages (2 native + A(3) + B(2) ⇒ `Halaman X dari 7`). **No migration, no new route, no new permission, no schema change** — navigation was already server-side (`?rm_page=`), so the change is a unified sequence plus a branch on the page's explicit kind.

**New:** `App\Modules\MedicalRecord\Support\RmeWorkspacePage` (immutable PII-free projection; `type` is an EXPLICIT field — never inferred from an id range/index/label/URL; `readonly` hard-coded true on the legacy factory), `App\Modules\MedicalRecord\Services\RmeWorkspacePageSequencer` (`sequenceFor`/`resolveActivePage` clamping a crafted `rm_page`/`nativeAnchorFor`), and 3 Blade partials under `resources/views/rme/visits/medical-record/partials/`: `legacy-archive-page` (read-only surface: zoom in/out/fit, fullscreen, `<img>` per page with PDF fallback), plus **extracted** `rm-page-navigator` and `rm-page-swipe-script` — extracted, NOT duplicated, so a second navigation system cannot grow; both the populated workspace and the zero-native-sheet empty state include the same two partials.

**Ordering (deliberate, not chronological):** native pages first in existing order, then the archive **newest document first**, pages ascending within each. Strict chronology would put every legacy page BEFORE every native page (the date rule guarantees legacy < earliest native), forcing a doctor to swipe through years of history to reach the page they must write on.

**Page-count authority:** the number of ACTUALLY RENDERED `trx_rme_legacy_record_pages` rows (one `loadCount` aggregate), NOT the declared `page_count` — a record can declare a count while nothing was rasterised. A record with 0 rendered pages contributes exactly ONE fallback page offering the inline source PDF; never dropped, never expanded into pages that could only 404.

**Clinical safety:** the editable figure is **not rendered at all** on an archive page (no inert-but-present canvas to aim a stylus at); the canvas + open editor keep `data-ignore-swipe`, and the archive viewer sets it **while zoomed** (a zoomed doctor is panning, not turning pages); new `beforeunload` guard + explicit confirm when closing the editor with live strokes, with a `submitting` flag so a save is never mistaken for data loss; `+ Tambah Halaman RM` always targets the canonical NATIVE handwriting endpoint, including while an archive page is active. Read-only is stated in TEXT ("Hanya Baca") and legacy page buttons carry an `L` prefix + spoken `aria-label` — never colour alone.

**Authorization unchanged and deliberately NOT re-derived:** the sequencer resolves nothing itself; the archive comes from `LegacyRmePatientHistoryService::publishedRecordsFor()` (read permissions + branch scope + doctor patient scope + published-only/VOID). A test asserts the sequencer source contains no `STATUS_PUBLISHED`/`branchIdsFor`/`doctorCanAccessPatient`/`LegacyRmeRecord::query`. Being listed is NOT authorization — bytes still stream through the policy-gated route which re-authorizes per request; **same branch alone still grants nothing**.

**Performance:** the patient's archive is now resolved **ONCE per request** and shared by the clinical history, the document rail and the page sequence (it was resolved TWICE before this sprint) — via a backward-compatible optional `?Collection $legacyRecords` parameter on both `LegacyRmePatientHistoryService::patientClinicalHistoryFor()` and `RmeWorkspaceDocumentPresenter::documentsFor()`. Rendered-page counts are one aggregate; only the ACTIVE page's image is fetched; no PDF is base64'd into the HTML.

**Gotcha:** `MedicalRecord::orderedHandwritingPages()` already has an `is_legacy` key meaning "legacy handwriting STORAGE path" (Sprint 60 read-through) — that is unrelated to the legacy PDF ARCHIVE.
