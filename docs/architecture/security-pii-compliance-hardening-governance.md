# ENT-9 — Security & PII Compliance Hardening Governance

Status: **LOCKED** (durable governance). Verified by
`php artisan foundation:security-compliance-check --strict`.

Governance section: `security_compliance_governance` (published into
`architecture:foundation-governance-summary`, informational — not wired into the
blocking combined decision).

Config: `config/security_compliance.php`. Scanner:
`App\Support\Security\SecurityComplianceScanner` (read-only). Governance service:
`App\Services\Foundation\SecurityComplianceGovernanceService`.

## Scope

Hardens KTP/NIK masking coverage, audit coverage, export permission gating, and
branch isolation across the modules to the enterprise standard. Read-only and
non-destructive — it verifies posture, mutates nothing, and never trusts a
request-supplied `branch_id`.

Out of scope: cross-branch patient search by name/KTP, weakening any existing
gate, external secret export, and any change to RME/payment/inventory/lab/
dashboard business workflows.

## Rules (ENT9-SEC001..ENT9-SEC012)

- **ENT9-SEC001** — Full KTP/NIK never render, export, or log. Identifiers are
  server-side only; UI/reports/exports/logs expose masked values. The sidebar is
  never a security boundary — every gate is enforced server-side.
- **ENT9-SEC002** — Masking helpers stay present and enabled (patient KTP masker,
  developer-console sensitive-value masker); disabling/removing one fails.
- **ENT9-SEC003** — No unmasked KTP/NIK display echo in Blade. A read-only view
  scan flags raw display echoes; form inputs / value bindings are excluded.
- **ENT9-SEC004** — Every data-export route is auth/permission gated in its fully
  resolved middleware stack (group middleware included).
- **ENT9-SEC005** — The immutable `sys_audit_logs` trail remains; sensitive
  access writes an audit row and never mutates history.
- **ENT9-SEC006** — Branch isolation trusts `BranchContext::requireId()`, never
  the request; cross-branch analytics stay permission-gated and read-only.
- **ENT9-SEC007** — No cross-branch patient search by name/KTP.
- **ENT9-SEC008** — The governance check is read-only and privacy-safe; output
  never contains raw KTP/NIK, patient rows, secrets, or credentials.
- **ENT9-SEC009** — No existing permission/policy/consent/room/completion gate
  may be weakened.
- **ENT9-SEC010** — ENT-5 / ENT-6 / ENT-7 / ENT-8 strict governance must stay GO.
- **ENT9-SEC011** — Scan patterns/field names live in `config/security_compliance.php`,
  never inline in app code.
- **ENT9-SEC012** — New PII fields, export routes, or audited surfaces must
  extend this contract with coverage and tests and pass this check first.

## Verification

```
php artisan foundation:security-compliance-check --strict
php artisan foundation:security-compliance-check --json
```

The check reports masking-helper presence, view-scan result (`views_scanned`,
`view_scan_findings`), export-gating result (`export_routes_total`,
`ungated_export_routes`), audit + branch-isolation posture, and the ENT-5/6/7/8
governance decisions. `--strict` returns non-zero on WATCH as well as FAIL.

Evidence artifact `security-compliance-check.json` is required in the CI and VPS
release-evidence profiles and is generated by `scripts/deploy-vps.sh`.

## Preservation of prior foundations

ENT-9 surfaces but never weakens the ENT-5 queue/failed-job, ENT-6
idempotency/outbox, ENT-7 developer-console, and ENT-8 health-check governance —
all four strict checks must remain GO for ENT-9 to be GO.
