# ENT-12 — Backup & Disaster Recovery Automation Governance (Durable Lock)

Status: **LOCKED** (ENT-12). Governance section: `backup_dr_governance`.
Readiness command: `foundation:backup-dr-check`.

This document is the durable lock for how DaengtisiaMS backs up its data and
proves it can recover. It builds on the NSF-10 `foundation:backup-verify` gate
and the ENT-11 deploy/rollback automation, and is enforced by
`App\Services\Foundation\BackupDrGovernanceService` (published into
`architecture:foundation-governance-summary` as `backup_dr_governance`) and the
read-only `App\Support\Backup\BackupDrScanner`, both driven by config
`config/backup_dr.php`.

## Why this exists

A database dump that has never been restored is not a proven backup. ENT-12
turns the existing pre-deploy backup into a real, retained, and **rehearsed**
disaster-recovery posture with measurable objectives, without ever endangering
the VPS pilot database.

## Automation surfaces

- `scripts/backup-vps.sh` — standalone, schedulable DB backup. Fail-fast
  (`set -euo pipefail`), `pg_dump` into the allowed backup directory
  (`storage/app/backups/deploy`), verify with `php artisan foundation:backup-verify`,
  then prune dumps older than `BACKUP_DR_RETENTION_DAYS` while keeping at least
  the minimum recent backups. Reads DB credentials only from the local
  environment example file at runtime; no secret is printed.
- `scripts/restore-rehearsal.sh` — non-production restore drill. Fail-fast,
  selects the latest verified backup, restores it into a **scratch** database
  (`REHEARSAL_DB`) whose name **must differ from the production database** (the
  drill aborts otherwise), verifies the restored table count, drops only the
  scratch database, and writes a non-sensitive `restore-rehearsal` evidence file
  (backup path/size, table count, RTO/RPO). It never restores over production
  and never calls the production restore helper.
- Production data restore stays the separate, explicit
  `scripts/restore_postgres.sh <backup_file>` step — never automatic.

## RTO / RPO objectives

Recovery objectives are declared in `config/backup_dr.php` and are measurable:

- **RTO** (Recovery Time Objective): `rto_minutes` — the maximum acceptable time
  to restore service. Pilot default: 60 minutes.
- **RPO** (Recovery Point Objective): `rpo_minutes` — the maximum acceptable data
  loss window. Pilot default: 1440 minutes (daily backup cadence).

Retention: `db_backup_retention_days` (default 14) with a `min_retained_backups`
floor so pruning never drops below the recoverable minimum.

## Rules (ENT12-BDR001..ENT12-BDR012)

- **ENT12-BDR001** — Backup is automated through the canonical `scripts/backup-vps.sh`.
- **ENT12-BDR002** — Every automated backup is verified (`foundation:backup-verify`) before it is trusted.
- **ENT12-BDR003** — Backups are retained with a bounded, pruned retention window.
- **ENT12-BDR004** — A rehearsable restore drill (`scripts/restore-rehearsal.sh`) exists and is fail-fast.
- **ENT12-BDR005** — Restore rehearsal NEVER targets the production database (scratch-only, guarded).
- **ENT12-BDR006** — Backup / rehearsal scripts carry no production-endangering command (config-not-code).
- **ENT12-BDR007** — RTO and RPO objectives are documented and measurable.
- **ENT12-BDR008** — DR evidence stays non-sensitive (path/size/counts only).
- **ENT12-BDR009** — The `backup-dr-check.json` evidence artifact is required per ci/vps profile.
- **ENT12-BDR010** — `foundation:backup-dr-check` is a mandatory pre-deploy gate (deploy script + CI).
- **ENT12-BDR011** — Backup/DR builds on and preserves the ENT-5..11 foundations (re-verified GO).
- **ENT12-BDR012** — New backup/DR automation registers here with tests first before shipping.

## Evidence & gate wiring

- `config/release_evidence.php` — `backup-dr-check.json` required in the `ci` and
  `vps` profiles; generated by `release:evidence-capture` and validated by
  `release:evidence-check`.
- `config/release_safety.php` — `foundation:backup-dr-check` in the pre-deploy
  gate list; `scripts/backup-vps.sh` + `scripts/restore-rehearsal.sh` in
  `deploy_gate_files`.
- `config/foundation_governance.php` — ENT-12 CI-gate registry entry.
- `scripts/deploy-vps.sh` and `scripts/ci/foundation-evidence-gates.sh` run
  `php artisan foundation:backup-dr-check` and capture its JSON artifact after
  the ENT-11 gate, preserving the ENT-8 cache-order hardening.

## Safety guarantees

- Read-only governance: the scanner and command never take a backup, run a
  restore, drop a database, or run any destructive command.
- Non-production only: restore rehearsals run against a scratch database and
  abort if the target equals the production database.
- No secret / PII / KTP / NIK is written to any DR evidence artifact.
- Never `migrate:fresh` / `db:wipe` on the VPS; `migrate --force` only.
