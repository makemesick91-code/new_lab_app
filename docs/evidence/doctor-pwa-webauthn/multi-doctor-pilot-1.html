identity_state = cryptographically_verified is written by exactly two code paths, both inside the Android Clinic App. A trusted device cannot be created from the server side — it needs a physical tablet completing a real enrolment, and a credential needs a human performing user verification at that device.

One nuance that lowers the cost of the doctor half, though not the device half: the WebAuthn credential is bound to the device, not the doctor, and the authorization table has supported many doctors per device since Phase 3. A second doctor on the existing tablet would need only an authorization and would reuse credential 2.

G. What unblocks the multi-doctor GO

  1. Hardware. At least one more physical Android clinic tablet, enrolled until cryptographically_verified, ideally at a branch other than SPN4 so the two-branch minimum is met by geography rather than by paperwork.
  2. Named doctors. All 14 non-pilot accounts are equally eligible on the data available, so there is no objective ranking to offer and one must not be invented.
  3. Provisioning, then enforcement. Device, authorization and a usable device-bound credential must all exist before any id joins the cohort.
  4. Ceremonies. Per doctor: Chrome login, protected request, independently initiated installed-PWA login, protected request — each against a fresh audit watermark, separating server-verified facts from operator-attested client context.
  5. Then set the cohort variable, rebuild config as daengtisiams, and reconcile covered / denied / allowed against the live doctor count.
