The signature counters are the load-bearing evidence — they are produced by the tablets' authenticators and cannot advance without that physical device signing a fresh challenge.

F. Two mistakes the process caught

CAUGHT BY VERIFICATION, NOT BY OBSERVATION

Credential registered against the wrong device. A credential intended for device 6 was created at the device 5 URL. The database could not say which tablet produced it: Android platform authenticators report AAGUID all-zeros with attestation none, and both counters were 0. Asked which tablet they had been holding, the operator answered not sure, so it was revoked as credential 4. A credential whose hardware cannot be established has no place in a device-trust pilot.

Ceremony performed by the wrong doctor. A login intended for drg Fiitri was in fact drg Nisa's third login on the Landak tablet, identified by user id, credential id and an identical user-agent hash. It was not counted.

The revoke reason stored on credential 4 reads iuohjg7rtfyedhfryf. The audit trail is append-only so that text is permanent. The real reason is uncertain physical origin, recorded here because the row itself does not say so.

G. What the server can and cannot prove

drg Nisa's Chrome and installed-PWA user agents are byte-identical, MD5 c6a91b89…, both reporting Chrome/152.0.0.0. So the distinction is split honestly:

  • Server-verified — two independent assertions on the same credential, minutes apart, each with its own session invalidation and its own counter increment.
  • Operator-attested only — that one was Chrome and the other the installed PWA. The server has no field that separates an Android PWA in standalone mode from the browser, and testimony is not promoted into a server fact.

The server can distinguish the two tablets. Every drg Nisa assertion carries MD5 c6a91b89…; every drg Fiitri assertion carries 980b68e0…. Different hardware, corroborated independently of anyone's account of events.

I. Rollback and boundary

Remove one doctor: delete their id from the cohort key and rebuild config as daengtisiams. Their device, authorization and credential all survive. Whole pilot: both feature flags false, rebuild config, expect denied 0 and allowed 15. Device, authorization and credential revocation stay terminal and are reserved for real compromise, never for rollback.

This GO authorises three doctors and nothing else. Not a fourth doctor, not a new device, not fleet-wide enforcement. global_permitted remains a source-controlled false that no host variable can reach, and the cohort ceiling of 5 can only be raised by a reviewed source change.
