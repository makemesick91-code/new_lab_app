# Enterprise Foundation Closure Runbook (ENT-16)

Operator runbook for running the Enterprise Foundation Closure GO/NO-GO and, on
GO, cutting the final `enterprise-foundation-go` tag that ends the initial
Enterprise Foundation Freeze.

## Purpose

Prove that ENT-1..ENT-16 are present, governed, evidenced, and inherited by
future work, then record an auditable GO/NO-GO closure decision. This runbook is
non-sensitive and contains no secret, credential, or unmasked KTP/NIK.

## When to Use

- Before declaring the enterprise foundation sequence closed.
- As a re-verification gate on every VPS deploy (the deploy script runs it).
- When auditing whether later work still inherits the ENT-5..16 rules.

## Prerequisites

- Local or VPS checkout at the ENT-16 GO tag or later.
- All ENT-5..15 readiness commands available (they are registered artisan commands).
- Route/config cache valid (the deploy script clears + rebuilds before gates — ENT-8 ordering).

## Safe Commands

Read-only, safe to run locally, in CI, and on the VPS:

```
php artisan foundation:enterprise-closure-check
php artisan foundation:enterprise-closure-check --json
php artisan foundation:enterprise-closure-check --strict
php artisan foundation:roadmap-check --strict
php artisan architecture:foundation-governance-summary
```

Expected GO state: decision `GO`, 16 completed roadmap entries, 13/13 closure
criteria met, all 11 mandatory gate decisions `GO`, `next_recommended_sprint`
`MON-1` (not stale).

## Forbidden Commands

Never run these — they are destructive and are NO-GO drift for closure:

- `php artisan migrate:fresh`
- `php artisan db:wipe`
- `php artisan schema:drop`
- `php artisan migrate:reset`

The closure gate itself never runs a deploy, backup, restore, load test, or
migration. Do not add any such command to the closure path.

## Evidence

- Artifact: `enterprise-closure-check.json` (required in the ci and vps
  release-evidence profiles; generated by CI and by `scripts/deploy-vps.sh`).
- Non-sensitive only: gate decisions, criteria met counts, readiness status.
- Never contains a secret, credential, environment value, or KTP/NIK.

## Rollback

Closure changes no runtime, schema, route, permission, or workflow, so there is
nothing to roll back functionally. If a closure GO was cut in error, follow the
standard `docs/runbooks/vps-deploy-rollback-runbook.md` path (backup-first, no
automatic data restore). Do not move an existing GO tag.

## Troubleshooting

- **NO-GO on a gate** — run that gate's own strict command (e.g.
  `foundation:health-check --strict`) and fix the underlying foundation; never
  relax the closure gate to pass.
- **Stale next sprint (WATCH)** — confirm ENT-16 is `completed` with a `go_tag`
  in `config/foundation_roadmap.php`; next must resolve to `MON-1`.
- **Missing evidence artifact** — confirm the ci/vps release-evidence profiles
  and `scripts/deploy-vps.sh` still generate `enterprise-closure-check.json`.

## Smoke Verification

On the VPS after deploy:

```
php artisan foundation:enterprise-closure-check --strict
php artisan foundation:roadmap-check --strict
php artisan release:evidence-check --profile=vps
curl -s http://127.0.0.1/health/ready
```

## Security

No secret/PII/full KTP/NIK in output or evidence. Health endpoints stay minimal.
Developer console stays permission-gated and audited.

## Owner

Platform / Foundation governance owner.

## Review Cadence

Re-review on every enterprise-scope sprint and at each VPS deploy that runs the
closure gate.
